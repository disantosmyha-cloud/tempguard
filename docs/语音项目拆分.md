# 语音/桌宠项目拆分

## 结论

本地语音/桌宠能力已经从 temguard 主仓库移出，放到独立项目：

```text
C:\path\to\tempguard-voice
```

temguard 主仓库只保留温度看门狗和告警服务。

## 为什么拆

- 语音依赖 Torch、CosyVoice、SVS、F5、模型权重，体积以 GB 计；
- 模型和录音不应进入 Git、npm 或普通源码包；
- 语音进程崩溃不应影响温度采样和关机逻辑；
- 模型/虚拟环境可以独立升级，不和 watchdog 的依赖互相污染。

## 为什么不做成 npm 包

语音引擎是 Python/Torch 服务，不是 Node 模块。把模型塞进 npm 包既慢又不可维护。

正确边界：

```text
tempguard（Python）  →  温度/告警
tempguard-voice（Python）→  语音/桌宠服务，127.0.0.1:8899
可选 dsh-plugin-petvoice（npm，薄 HTTP 客户端）
```

npm 只适合做 **DSH 前端的薄插件**，不适合承载模型权重。

## 当前运行时

独立语音项目使用自己的：

- `.venv`
- `models/`
- `checkpoints/`
- `cosyvoice/`
- `svs/`
- `pet.db`
- `logs/`

这些全部在本项目 `.gitignore` 之外，不进入 temguard 仓库。

## 如果以后要发 npm

只发类似：

```text
dsh-plugin-petvoice  —— 调用 http://127.0.0.1:8899 的薄客户端
```

不要把语音模型、录音或 `pet.db` 打进 npm。
