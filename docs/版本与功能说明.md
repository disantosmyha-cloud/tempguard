## 2. 架构

```text
LibreHardwareMonitor / nvidia-smi / pynvml
                │
                ▼
        core/sensors.py
                │  CPU/GPU 温度
                ▼
         core/fuse.py  ── 四态熔断
                │
                ▼
           main.py
          ├─ CSV 日志
          ├─ terminate / shutdown
          ├─ 动作日志/重试
          └─ alertd HTTP
                │
                ▼
            alertd.py
       SQLite outbox / worker
                │
      ┌─────────┼──────────┐
      ▼         ▼          ▼
    email     QQ OneBot    其他适配器
```

DSH 插件不启动服务，只读取 `/health` 和温度 CSV，并通过 `/alert` 投递告警。

## 3. 核心功能

### 3.1 温度看门狗

- 四态：`safe` / `warning` / `terminate` / `shutdown`；
- 默认阈值：警告 90°C、终止 93°C 持续 20 分钟、关机 95°C 连续 3 次、恢复 88°C；
- 冷启动 180 秒保护：只对 Windows 冷启动生效；同一启动周期内重启不会重新获得；
- 传感器新鲜度：20 秒无新读数记为失效；全部传感器失效 300 秒后按配置执行 `warn` 或 `shutdown`；
- 部分传感器失效：警告，继续使用剩余传感器；
- 熔断计时持久化：重启进程不会重置 20 分钟终止计时；
- 动作日志：terminate/shutdown 失败后按 `actions.retry_seconds` 重试；
- 网络告警失败：本机蜂鸣 + `logs/critical-alerts.log`；
- 演习模式：`actions.dry_run: true` 时不会真正终止进程或关机；
- 单实例锁：防止重复采样/重复关机。

### 3.2 传感器

- CPU：LibreHardwareMonitor Web JSON → `psutil` 兜底；
- GPU：`nvidia-smi` → LibreHardwareMonitor → `pynvml`；
- 读数做合理范围过滤，读不到记为 `None`，主循环不崩；
- 温度 CSV 超过 20MB 自动轮转。

### 3.3 alertd 告警服务

- 监听 `127.0.0.1:8765`；
- SQLite 持久化 outbox，进程重启不丢 pending；
- `TRIP > WARN > INFO` 优先级；
- 多 worker，适配器并行 fanout；
- 每个适配器独立超时/重试/抖动；
- 失败自动退避重试，超过上限进入 failed；
- `/retry` 手动补发；
- `wait: true` 等待真实投递结果；
- 幂等键，避免重复投递；
- `required_adapters`：TRIP 必须由指定通道确认；
- 适配器熔断器：连续失败后冷却；
- token 鉴权、健康检查、发送日志、历史保留。

### 3.4 告警通道

当前重点：

- `email`：QQ 邮箱 SMTP，当前作为 TRIP 的 required 通道；
- `qq-onebot`：NapCat + OneBot，作为辅助通道；
- 其他可插拔：企业微信、飞书、钉钉、Telegram、Discord、Slack、AstrBot、iLink、微信桥。

真实使用建议：

```yaml
required_adapters:
  - email
```

个人 QQ 不作为唯一关键通道。

### 3.5 安全与运维

- Windows DPAPI 保存 alertd token、AstrBot key、邮箱授权码；
- 配置只写 `${secret:name}` 占位符；
- `secrets.dat`、`config.local.yaml`、`logs/`、`runtime/` 不入库；
- AstrBot、NapCat、alertd 全部绑定 loopback；
- 计划任务随登录启动，失败自动重启；
- NapCat supervisor 自动拉起 OneBot。

### 3.6 DSH 插件

`dsh-plugin-tempguard@0.1.5`：

- `tempguard_status`：读取 alertd 健康、outbox/pending、required 通道和最新 CSV 温度；
- `tempguard_alert`：通过 alertd 发送 INFO/WARN/TRIP；
- `node --test` 测试通过；
- npm 包带 repository/homepage/bugs/keywords 元数据。

- 语音/桌宠在独立项目 `tempguard-voice`，模型/虚拟环境不入主仓库，见 [语音项目拆分](语音项目拆分.md)；

## 6. 当前边界

- 不是安全关键认证系统，不能替代 UPS/外部硬件保护；
- 外部 dead-man switch 未配置（`monitor.heartbeat_url` 为空）；
- QQ/NapCat 是个人号方案，受账号风控和协议变化影响；
- 没有做真实 100°C 烤机或硬件传感器失效演练；
- 用户执行 `shutdown /a` 取消关机后，temguard 无法直接感知；
- 传感器“冻结值”目前只能辅助判断，不能完全证明 LHM 数据新鲜。
