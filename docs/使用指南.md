# temguard 使用与开源指南

这份文档写给不想改代码、只想把项目跑起来、调好参数并发布到 GitHub 的人。

---

## 1. 项目一句话

temguard 每隔几秒读一次 CPU/GPU 温度，写进 CSV；温度持续超限时按四态升级：

```text
安全 → 警告 → 终止进程 → 关机
```

所有危险动作都有“演习模式”，可以只看打印不动手。

---

## 2. 它是怎么工作的

```text
LibreHardwareMonitor 的 data.json ─┐
nvidia-smi / pynvml ───────────────┼─> core/sensors.py
psutil（Linux/macOS 兜底）─────────┘        │
                                           ▼
                                      main.py 主循环
                                           │
                              ┌────────────┼────────────┐
                              ▼            ▼            ▼
                        logs/temps.csv  core/fuse.py  core/notify.py
                                           │
                              ┌────────────┴────────────┐
                              ▼                         ▼
                       终止配置的进程              延迟关机
```

一句话：`sensors.py` 负责“读”，`fuse.py` 负责“判”，`main.py` 负责“执行和循环”，`notify.py` 负责“喊人”，`config.yaml` 负责“调参数”。

## 4. 每个文件具体做什么

### `main.py`

主循环，项目的大门。

关键函数：

| 函数 | 作用 |
|---|---|
| `load_config()` | 读取 `config.yaml` |
| `_open_log()` | 打开/创建 `logs/temps.csv`，自动写表头；旧表头会自动备份 |
| `_find_processes()` | 按进程名找进程，跳过自己和自己的父进程 |
| `_handle_terminate()` | 处理“终止进程”：演习打印，真实模式真杀 |
| `_handle_shutdown()` | 处理“关机”：演习打印，真实模式执行 `shutdown /s /t 60` |
| `_handle_state()` | 只在状态变化时发告警，避免每 5 秒刷屏 |
| `run()` | 主循环：采样 → 写 CSV → `fuse.feed()` → 执行状态动作 |
| `main()` | 解析命令行参数，加载配置 |

主循环里每一轮都包在 `try/except` 中：单次读取失败、写日志失败、通知失败都不会让程序退出。

### `core/sensors.py`

负责“读”，所有函数读不到都返回 `None`，不抛异常。

| 函数 | 作用 |
|---|---|
| `read_cpu_temperature()` | 读 CPU 温度，优先 LHM，Windows 下回退 psutil（通常没有） |
| `read_gpu_temperature()` | 读 GPU 温度：`nvidia-smi` → LHM → `pynvml` |
| `read_cpu_usage()` | 读 CPU 总占用率（当前四态熔断只看温度，这个函数先保留） |
| `read_temperatures(config)` | 返回 `{"cpu": 87.5, "gpu": 54.0}`，主循环用的就是它 |

LHM 数据来自 `http://127.0.0.1:8085/data.json`，带 0.5 秒缓存和 10 秒失败冷却。

### `core/fuse.py`

负责“判”，只做四态判断，不碰进程、不写文件。

核心规则：

- 取 CPU/GPU 里最热的那个温度；
- `warning_c`：进入“警告”；
- 连续 `≥ terminate_c` 满 `terminate_seconds`：进入“终止进程”；
- 连续 `shutdown_samples` 次 `≥ shutdown_c`：进入“关机”；
- 低于 `reset_c`：所有计时/计数清零；
- 中间掉到对应阈值以下：对应计时/计数重来；
- 一个温度都读不到：按“警告”处理，但不基于旧数据继续累计。

`python core\fuse.py` 会跑末尾的假数据测试，能看到完整升级过程。

### `core/notify.py`

负责“喊人”。

- `notify()` 加时间戳打印；
- 预留 `_push_phone()`，以后接企业微信/钉钉/Server酱/Bark；
- 控制台编码不支持某个字符时会替换，不会让程序崩掉。

### `config.yaml`

所有可调数值都在这里，改完重启程序即可，不用改 Python 代码。

### `requirements.txt`

```text
pyyaml>=6.0
psutil>=5.9
```

LHM 不是 Python 包，需要单独下载运行。

### `README.md` / `LICENSE` / `.gitignore`

- README：GitHub 首页说明；
- LICENSE：MIT，别人可以自由使用、修改、分发；
- .gitignore：防止日志、`__pycache__`、本地配置、密钥被提交。

## 5. 安装与第一次运行

### 5.1 安装 Python 依赖

在项目目录打开 PowerShell：

```powershell
pip install -r requirements.txt
```

### 5.2 安装并运行 LibreHardwareMonitor

1. 打开 [LibreHardwareMonitor Releases](https://github.com/LibreHardwareMonitor/LibreHardwareMonitor/releases)；
2. 下载 `LibreHardwareMonitor.zip` 并解压；
3. 右键 `LibreHardwareMonitor.exe`，选择“以管理员身份运行”；
4. 菜单 **Options → Remote Web Server → Run**；
5. 长期挂机再勾选：
   - **Options → Run On Windows Startup**
   - **Start Minimized**

确认网页能打开：

```text
http://127.0.0.1:8085/data.json
```

看到一大段 JSON 就说明正常。

### 5.3 先自检

```powershell
python core\sensors.py
```

正常会看到类似：

```text
CPU 温度：87.2 °C
GPU 温度：54.0 °C
CPU 占用：8.0 %
```

CPU 显示“读不到”时，先检查 LHM 是否在运行、Web Server 是否已 Run。

### 5.4 看四态演示

```powershell
python core\fuse.py
```

### 5.5 单次检查

```powershell
python main.py --once
```

### 5.6 正常挂机

```powershell
python main.py
```

按 `Ctrl+C` 干净退出。

控制台只在状态变化时打印（警告、恢复、终止、关机），温度正常时保持安静；每 5 秒的采样仍然会写进 `logs/temps.csv`。

### 5.7 后台运行（无黑窗口）

`python main.py` 是前台运行，关掉控制台 = 停止监控。

想让程序在后台跑、不用一直留着黑窗口，可以用 `pythonw.exe` 或计划任务。本机已经注册了 `temguard` 计划任务：

- 程序：`pythonw.exe`
- 参数：`-X utf8 main.py`
- 触发：当前用户登录时
- 权限：最高权限
- 工作目录：`D:\PythonStudy\tempguard`
- 窗口：无（后台运行）

查看是否在跑：

```powershell
Get-Process pythonw
Get-Content logs/temps.csv -Tail 5
```

停止/启动：

```powershell
Stop-ScheduledTask -TaskName temguard
Start-ScheduledTask -TaskName temguard
```

关闭黑窗口不会影响这个后台任务；但如果你手动用 `python main.py` 启动了一个前台实例，关闭那个窗口就会停止那个实例。

### 5.8 公开配置和本机真实配置

仓库里的 `config.yaml` 默认是**演习模式**（`dry_run: true`），这是给 GitHub 上其他人的安全默认值。

本机如果存在 `config.local.yaml`，`main.py` 会**优先读取它**。当前本机的真实模式参数就在这个文件里，而它已被 `.gitignore` 忽略，不会上传。

```text
python main.py                      # 本机有 config.local.yaml → 真实模式
python main.py --config config.yaml # 强制使用公开配置 → 演习模式
python main.py --dry-run            # 不管配置如何 → 强制演习
```

本机想改真实模式的参数，改 `config.local.yaml`，不要改公开的 `config.yaml`。

## 6. `config.yaml` 参数详解

公开文件结构（本机真实参数在 `config.local.yaml`，结构相同）：

```yaml
sample:
  interval_seconds: 5
  log_file: logs/temps.csv

thresholds:
  warning_c: 90
  terminate_c: 93
  shutdown_c: 95
  reset_c: 88
  terminate_seconds: 1200
  shutdown_samples: 3

safety:
  startup_grace_seconds: 180
  require_cool_baseline: true

actions:
  dry_run: true
  terminate_processes:
    - blender.exe
    - python.exe
  shutdown_delay_seconds: 60

sensors:
  cpu: true
  gpu: true

notify:
  print: true
  phone:
    webhook: ""
```

### 6.1 `sample`：采样

| 参数 | 当前值 | 怎么改 |
|---|---|---|
| `interval_seconds` | 5 | 每隔几秒检查一次。改小反应快但更频繁；建议 3–10 秒 |
| `log_file` | `logs/temps.csv` | 日志路径，相对项目根目录；也可以写绝对路径 |

### 6.2 `thresholds`：温度阈值

| 参数 | 当前值 | 含义 | 调整建议 |
|---|---|---|---|
| `warning_c` | 90 | 达到就警告 | 应低于 `terminate_c` |
| `terminate_c` | 93 | 连续超这个温度才可能终止进程 | 根据 CPU/GPU 规格设置 |
| `shutdown_c` | 95 | 连续超这个温度才可能关机 | 应高于 `terminate_c`，接近硬件危险线 |
| `reset_c` | 88 | 低于此值算恢复正常，全部清零 | 建议比 `warning_c` 低 2–5°C |
| `terminate_seconds` | 1200 | 连续 ≥93°C 满多少秒才终止 | 1200=20 分钟；测试可改 60 |
| `shutdown_samples` | 3 | 连续多少次 ≥95°C 才关机 | 3 次 × 5 秒 = 约 15 秒 |

注意：判断用的是 CPU/GPU 中**最热**的那个温度。

### 6.2.1 `safety`：开机保护

| 参数 | 当前值 | 说明 |
|---|---|---|
| `startup_grace_seconds` | 180 | 程序启动后多少秒内只警告，不终止/关机 |
| `require_cool_baseline` | `true` | 必须先读到一次低于 `warning_c` 的正常温度，才允许动作 |

为什么需要它：LHM/驱动刚启动时，传感器偶尔会报出 100°C+ 的假高温。没有这层保护，3 次采样就可能直接关机，这显然不科学。

保护期结束时会清空保护期内累计的高温次数/时长；如果一直没读到正常温度，就一直只警告。

### 6.3 `actions`：动作

| 参数 | 当前值 | 说明 |
|---|---|---|
| `dry_run` | 公开 `true` / 本机 `false` | `false`=真实模式；`true`=演习模式 |
| `terminate_processes` | `blender.exe`、`python.exe` | 要终止的进程名，不区分大小写 |
| `shutdown_delay_seconds` | 60 | 真关机前留 60 秒取消；取消命令 `shutdown /a` |

**重要**：`dry_run: false` 时，达到条件会真的杀进程、真的关机。公开的 `config.yaml` 保持 `true`，本机 `config.local.yaml` 才是 `false`。

`python.exe` 范围很宽，会匹配所有 Python 进程。如果你只想终止某个训练脚本，建议把进程名改具体，例如：

```yaml
terminate_processes:
  - blender.exe
  - ffmpeg.exe
```

或者把你的训练程序打包/改名为一个独立的 exe，再填那个名字。

### 6.4 `sensors`：传感器开关

| 参数 | 当前值 | 说明 |
|---|---|---|
| `cpu` | true | 关掉后不读 CPU 温度 |
| `gpu` | true | 关掉后不读 GPU 温度 |

### 6.5 `notify`：通知

| 参数 | 当前值 | 说明 |
|---|---|---|
| `print` | true | 打印到屏幕 |
| `phone.webhook` | 空 | 以后填手机推送地址；现在留空 |

## 7. 日志怎么读

文件：`logs/temps.csv`

表头：

```text
time,cpu,gpu,hottest,state,reason
```

示例：

```csv
time,cpu,gpu,hottest,state,reason
2026-10-22 00:15:30,88.0,54.0,88.0,safe,
2026-10-22 00:16:00,91.2,54.0,91.2,warning,CPU 91.2°C ≥ 警告线 90°C
2026-10-22 00:36:00,94.0,54.0,94.0,terminate,CPU 94.0°C 已连续 1200s ≥ 93°C
```

- `state` 是英文四态：
  - `safe` 安全
  - `warning` 警告
  - `terminate` 终止进程
  - `shutdown` 关机
- `reason` 是中文原因，正常时为空。
- 旧表头不匹配时，会自动改名备份成 `temps.legacy-时间.csv`。

## 8. 常见修改配方

### 配方 1：先演习，确认误报

```yaml
actions:
  dry_run: true
```

### 配方 2：测试完整升级流程（不用等 20 分钟）

先备份 `config.yaml`，然后临时改：

```yaml
thresholds:
  warning_c: 80
  terminate_c: 85
  shutdown_c: 88
  reset_c: 75
  terminate_seconds: 10
  shutdown_samples: 2

actions:
  dry_run: true
```

这样几十秒就能看到“警告 → 终止进程 → 关机”的演习输出。测完记得改回真实阈值。

### 配方 3：只警告，不动作

```yaml
actions:
  dry_run: true
```

或者把 `terminate_processes` 设为空列表：

```yaml
terminate_processes: []
```

### 配方 4：取消已经计划中的关机

在 PowerShell 运行：

```powershell
shutdown /a
```

### 配方 5：更换日志位置

```yaml
sample:
  log_file: D:/tempguard-logs/temps.csv
```

### 配方 6：关掉 CPU 或 GPU 监控

```yaml
sensors:
  cpu: false
  gpu: true
```

## 9. 安全与注意事项

1. **真实模式不是演习**：`dry_run: false` 会真的终止进程、真的关机。
2. **关机有 60 秒缓冲**：可以在 PowerShell 运行 `shutdown /a` 取消。
3. **进程名要具体**：`python.exe` 会匹配所有 Python 进程，可能误杀其他脚本。
4. **阈值不要照抄**：不同 CPU/GPU 的正常温度不同。先观察 `logs/temps.csv` 几天再定。
5. **LHM 要管理员运行**：否则 CPU 温度可能读不到。
6. **不要让 LHM 的 Web Server 暴露到公网**：默认监听 `127.0.0.1` 即可。
7. **手机推送 webhook 是密钥**：不要提交到 GitHub；以后用环境变量或本地配置文件保存。
8. **开机假高温不会直接关机**：启动后 180 秒内、且没有读到正常温度前，fuse 只警告，不执行终止/关机。

## 10. 常见问题

### CPU 温度一直是“读不到”

依次检查：

1. LHM 是否正在运行；
2. LHM 菜单 **Options → Remote Web Server → Run** 是否勾选；
3. `http://127.0.0.1:8085/data.json` 是否能打开；
4. LHM 是否以管理员身份运行；
5. 是否改过端口（改过就设置环境变量 `TEMPGUARD_LHM_URL`）。

### GPU 温度读不到

先运行：

```powershell
nvidia-smi --query-gpu=temperature.gpu --format=csv,noheader,nounits
```

没有输出就检查 NVIDIA 驱动；AMD/Intel 显卡请确认 LHM 正在运行。

### `main.py` 一启动就警告

当前 CPU 可能确实到了 `warning_c`。先看 `python main.py --once` 和 `logs/temps.csv`，确认是真实温度还是阈值设得太低。

### 日志被 Excel 占用

关闭 Excel 再运行，或者把 `log_file` 换一个路径。

### 程序好像没反应

用前台运行看输出：

```powershell
python main.py
```

不要用 `pythonw` 或双击隐藏窗口运行，否则看不到报错。

## 11. 开源到 GitHub

### 11.1 开源前检查

1. **日志不要提交**：`.gitignore` 已经忽略 `logs/*.csv`。
2. **本地配置不要提交**：`config.local.yaml`、`.env` 已被忽略。
3. **手机 webhook 不要提交**：现在是空字符串；以后填了要改成环境变量。
4. **不要提交 LHM 的 exe/dll**：它是第三方软件，体积大、有独立许可证，让用户自己去 Releases 下载。
5. **公开版默认演习模式**：仓库里的 `config.yaml` 已经是 `dry_run: true`；本机真实模式放在被忽略的 `config.local.yaml` 里，不要把它提交上去。
6. **保留 LICENSE**：项目已经是 MIT，别人使用更方便。

检查命令：

```powershell
git status --short
```

确认没有 `logs/temps.csv`、`__pycache__`、`config.local.yaml`、webhook、密码。

到 [git-scm.com](https://git-scm.com/) 下载安装 Git for Windows，安装时一路默认即可。
