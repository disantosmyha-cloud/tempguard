# 告警适配器：官方平台、QQ、个人微信

`alertd` 的出口分成“可插拔适配器”，代码在 `adapters/`。每个适配器只负责一件事：把统一的 `Alert` 发到某个平台。

```text
adapters/
├─ base.py           # Adapter / Alert 接口
├─ manager.py        # 逐个发送、逐适配器重试、汇总结果
├─ registry.py       # 从 config.yaml 构建适配器
├─ wecom.py          # 企业微信群机器人 Webhook
├─ feishu.py         # 飞书 / Lark Webhook
├─ dingtalk.py       # 钉钉 Webhook（加签）
├─ telegram.py       # Telegram Bot API
├─ discord.py        # Discord Webhook
├─ slack.py          # Slack Incoming Webhook
├─ email.py          # SMTP
├─ qq_onebot.py      # QQ OneBot v11 HTTP API
├─ wechat_ilink.py   # 个人微信 iLink HTTP 客户端（clean-room）
├─ wechat_hook.py    # Wechaty / WeChatFerry / 其它微信桥
└─ astrbot.py        # 可选的 AstrBot 适配器
```

全部配置在 `config.local.yaml` 的 `alertd.adapters` 列表里。

---

## 1. 企业微信群机器人

```yaml
- name: wecom-group
  type: wecom
  enabled: true
  webhook: "https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=..."
  mentioned_list: []
  mentioned_mobile_list: []
  timeout_seconds: 5
```

官方 Webhook，最稳。适合群告警，不需要 AstrBot。

---

## 2. 飞书 / Lark

```yaml
- name: feishu
  type: feishu
  enabled: true
  webhook: "https://open.feishu.cn/open-apis/bot/v2/hook/..."
  secret: ""          # 机器人开启“签名校验”时才填
  timeout_seconds: 5
```

---

## 3. 钉钉

```yaml
- name: dingtalk
  type: dingtalk
  enabled: true
  webhook: "https://oapi.dingtalk.com/robot/send?access_token=..."
  secret: ""          # 机器人开启“加签”时才填
  timeout_seconds: 5
```

如果填了 `secret`，适配器会自动追加 `timestamp` 和 `sign` 参数。

## 4. Telegram

## 8. QQ：OneBot v11

不直接实现 QQ 协议，而是接 OneBot 实现（NapCat / Lagrange 等）的 HTTP API：

```yaml
- name: qq-onebot
  type: qq_onebot
  enabled: true
  base_url: "http://127.0.0.1:3000"
  access_token: ""
  target_type: "group"      # group 或 private
  target_id: "123456789"
  timeout_seconds: 5
```

请求：

```text
POST /send_group_msg    {"group_id":"...","message":"..."}
POST /send_private_msg  {"user_id":"...","message":"..."}
```

如果 OneBot 实现要求鉴权，填 `access_token`。

## 9. 个人微信：iLink HTTP 客户端

这是 clean-room 实现的 iLink 客户端，只实现“发文本告警”，不复制 AstrBot 代码。

```yaml
- name: personal-wechat-ilink
  type: wechat_ilink
  enabled: true
  base_url: "https://ilinkai.weixin.qq.com"
  bot_token: "..."
  to_user_id: "...@im.wechat"
  context_token: "..."
  timeout_seconds: 15
```

### 重要限制

iLink 的 `context_token` 来自“用户最近一次给机器人发的消息”。它可能过期或只能用一次。失败时常见：

```text
ret=-2 errcode=0 errmsg=prepare failed
```

处理方式：

1. 在微信里给机器人发一条消息，刷新 `context_token`；
2. 从 iLink 配置/日志里更新 `context_token`；
3. 重启 alertd。

所以：

- 个人微信 **不适合作为唯一的无人值守告警通道**；
- 真正稳定的告警建议用企业微信群机器人 / 飞书 / 钉钉 / Telegram / 邮件；
- AstrBot 的微信适配器同样受这个上下文 token 限制，不是它独有的问题。

## 10. 其它微信桥：Wechaty / WeChatFerry

如果你已经有本地微信桥，只要它提供一个 HTTP 发送接口：

```yaml
- name: wechat-bridge
  type: wechat_hook
  enabled: true
  url: "http://127.0.0.1:8080/send"
  token: ""
  timeout_seconds: 5
```

alertd 会 POST：

```json
{
  "level": "TRIP",
  "message": "CPU 96.0°C 连续 3 次 ≥ 95°C",
  "text": "2026-10-22 21:00:00 [熔断] ...",
  "timestamp": "2026-10-22 21:00:00",
  "source": "temguard"
}
```

桥返回 2xx 即成功；返回 `{"ok": false}` 视为失败。

## 11. 可选：AstrBot

保留 AstrBot 适配器是为了个人微信/QQ 等非官方协议由它维护；官方平台可以直接用上面的独立适配器。

```yaml
- name: astrbot
  type: astrbot
  enabled: true
  base_url: "http://127.0.0.1:6185"
  api_key: "abk_..."
  umos:
    - "weixin_personal_mrhg:FriendMessage:...@im.wechat"
  timeout_seconds: 5
```

如果 `alertd.adapters` 里没有启用 `astrbot`，但 `notify.astrbot.enabled: true`，会自动加载 `astrbot-legacy`，兼容旧配置。

## 13. 安全

- Webhook、Bot Token、iLink Token、邮箱授权码只填 `config.local.yaml`；
- 公开的 `config.yaml` 全部保持空字符串/`enabled: false`；
- alertd 默认只监听 `127.0.0.1`；
- `actions.protect_keywords` 包含 `astrbot`、`alertd`，避免温度熔断误杀告警服务。
